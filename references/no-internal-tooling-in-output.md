# No Internal Tooling in Output

Two related rules that apply to every skill in this library, not case by case.

## 1. External-facing content stays project-only

Anything a skill sends outside this session — a GitHub issue, a PR description or comment, a commit message, or anything else posted somewhere another person or system will read it as a standalone artifact — must never mention this plugin, "agent-harness," or any skill by name. Write it exactly as a person on the project would write it directly: pure project/feature context, nothing about how it was produced.

Concretely, this means no:
- "Generated by the `slice-to-issues` skill" or any attribution line
- Labels, tags, or branch names that name a skill (`slice:`, `breakdown:`, etc.) — use plain project vocabulary instead (`feature:<slug>`, not `slice:<slug>`)
- Links back to an internal planning doc phrased as "see the SKILL.md process" or similar
- Any reference to "agent-harness," the plugin, or this being AI/agent-generated

## 2. Generated documents contain only project content

A saved document (a PRD, an implementation plan, a spec, a slice list, etc.) is written for the project — a stakeholder, a teammate, or a future session reading it back — not for routing between skills. It should never contain meta-commentary like "this is ready to hand to `breakdown-feature-implementation`" or "cross-reference the `security-and-hardening` skill" inside the document body itself.

That kind of next-step guidance belongs in the chat reply to the user when the skill reports back — never inside the file. A reader of the saved document later shouldn't see any trace of the tool that produced it.

## Applying this

When a skill's Process section says to draft a document, the document's own template/sections should be checked against both rules before saving: no skill/plugin names, no meta-commentary about which skill comes next, nothing that reads as generated-by-a-tool rather than written by a person on the project. When a skill's Process section says to post something externally (an issue, a PR, a comment), the same check applies before it's sent.
